## NetworkHelper (networking.dart)

NetworkHelper는 API URL을 받아 실제 HTTP 요청을 보내고, 응답으로 받은 JSON 문자열을 jsonDecode로 파싱해 반환하는 역할을 한다.

```dart
import 'dart:convert';
import 'package:http/http.dart' as http;

class NetworkHelper {
  NetworkHelper(this.url);

  final String url;

  Future<dynamic> getData() async {
    Uri uri = Uri.parse(url);

    http.Response response = await http.get(uri);

    if (response.statusCode == 200) {
      String data = response.body;
      return jsonDecode(data);
    } else {
      print('Error: ${response.statusCode}');
      return null;
    }
  }
}
```

### http 패키지

Flutter에서 REST API 요청을 보낼 때 가장 널리 사용되는 패키지는 http 패키지이다.
이 패키지를 이용하면 GET, POST 같은 기본 HTTP 요청을 손쉽게 보낼 수 있으며,
서버로부터 받은 응답(Response)을 통해 상태 코드와 데이터(body)를 확인할 수 있다.
특히 네트워크 통신을 비동기 방식으로 처리하기 때문에 UI가 멈추지 않고 자연스럽게 동작한다.

### jsonDecode
서버에서 온 응답 데이터는 대부분 JSON 문자열 형태로 전달된다.
Flutter에서는 이 JSON 문자열을 그대로 사용할 수 없기 때문에,
jsonDecode()를 이용해 Dart에서 사용할 수 있는 Map 또는 List 형태로 변환한다.
이 과정을 통해 "temp": 22 같은 값을 weatherData['temp']처럼 쉽게 접근할 수 있다.

## WeatherModel (weather.dart)

WeatherModel 클래스는 사용자의 현재 위치 기반으로 날씨 데이터를 가져오는 역할을 담당한다.

```dart
class WeatherModel {

  Future<dynamic> getLocationWeather() async {
    Location location = Location();
    await location.getCurrentLocation();

    NetworkHelper networkHelper = NetworkHelper(
      '$openWeatherMapURL'
          '?lat=${location.latitude}'
          '&lon=${location.longitude}'
          '&appid=$apiKey'
          '&units=metric',
    );

    var weatherData = await networkHelper.getData();
    return weatherData;  // Future<dynamic>
  }
}
```

### 비동기 처리(Future/async/await)

- API 호출은 시간이 오래 걸릴 수 있으므로 비동기 방식으로 실행해야 한다.
- async로 선언된 함수는 항상 Future를 반환한다.
- await는 해당 작업이 끝날 때까지 기다린 뒤 다음 코드 실행.
- Flutter에서 API 호출 시 반드시 필요한 구조.

### 서비스 분리(NetworkHelper, Location)

Flutter에서는 보통 역할을 분리해 모듈화한다.
- Location() → 위치 가져오는 역할
- NetworkHelper() → API 요청 기능
- WeatherModel → 이 둘을 연결해 최종 날씨 데이터를 제공
- 이렇게 하면 테스트하기 쉽고, 유지보수에도 유리해진다.

### API URL 구성 방식

```ruby
https://api.openweathermap.org/data/2.5/weather
?lat=위도
&lon=경도
&appid=API키
&units=metric
```

- 문자열 안에서 ${location.latitude} 같은 형태로 변수 주입(String interpolation) 사용
- units=metric → 섭씨 온도
이 URL은 그대로 NetworkHelper에 전달되어 GET 요청이 실행된다.


## LoadingScreen (loading_screen.dart)
LoadingScreen은 앱이 시작될 때 위치 기반 날씨 데이터를 가져오고, 데이터가 준비되면 자동으로 다음 화면(LocationScreen)으로 이동하는 역할을 한다.

### initState()

```dart
@override
void initState() {
  super.initState();
  _init();
}
```

- 로딩 화면이 생성되자마자 딱 한 번 실행되는 초기 로직을 넣는 곳.
- API 요청처럼 “앱 실행 시 바로 해야 하는 작업”을 넣기 위해 initState를 활용한다.

### 비동기 초기화 (_init, getLocationData)
```dart
Future<void> _init() async {
  await getLocationData();
}
```
- 날씨 데이터를 가져오는 작업은 시간이 걸리므로 비동기(async/await) 구조로 처리한다.
- 이 방식 덕분에 UI가 멈추지 않고 스피너 애니메이션이 자연스럽게 유지됨.

### Navigator.push로 화면 이동
```dart
Navigator.push(
  context,
  MaterialPageRoute(
    builder: (context) {
      return LocationScreen(locationWeather: weatherData);
    },
  ),
);
```
- 데이터를 모두 받아온 뒤 다음 화면으로 이동시킨다.
- WeatherModel로 받은 JSON 데이터를 그대로 LocationScreen으로 전달함.
- Flutter의 기본적인 라우팅 방식(Navigator) 예제이기도 해서 중요하다.

### 로딩 애니메이션 (flutter_spinkit)

```dart
SpinKitDoubleBounce(
  color: Colors.blue,
  size: 100.0,
)
```
- API 호출이 끝날 때까지 사용자 경험을 부드럽게 만들어주는 로딩 위젯.
- 별도 패키지(flutter_spinkit)를 활용해 로딩 인터랙션(UI/UX 개선)을 구현

## LocationScreen (location_screen.dart)

LocationScreen은 날씨 데이터를 받아 화면(UI)에 표시하기 위한 화면이다.

### State 클래스의 멤버 변수

```dart
WeatherModel weather = WeatherModel();
int? temperature;
String? weatherIcon;
String? cityName;
String? weatherMessage;
```

- API에서 받아온 데이터를 화면 UI에 표시하기 위해 변수로 보관한다.
- ?는 null safety → 초기값이 없을 수 있다는 의미.

### JSON 데이터 파싱

OpenWeatherMap에서 받은 JSON 데이터를 Map처럼 접근한다.
- weatherData['main']['temp']
- weatherData['weather'][0]['id']
- weatherData['name']
이 값들을 화면에서 사용할 형식(int, String)으로 변환한다.
